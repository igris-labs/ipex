IPEX supports repeated, focused work. Keep the surrounding interface quiet so a person can scan the data, recognize the current mode, and identify the next action.

## Rest, intent, engagement, outcome

Design these four phases for an interactive control:

| Phase   | What the person needs                              | Treatment                                                 |
| ------- | -------------------------------------------------- | --------------------------------------------------------- |
| Rest    | Recognize that the control is available.           | A stable boundary and readable label.                     |
| Intent  | See the current pointer or keyboard target.        | A stronger foreground, hover treatment, or visible focus. |
| Engaged | Recognize the selected, pressed, or editing state. | A persistent indicator or engaged material.               |
| Outcome | Understand processing, completion, or failure.     | A message and, where useful, semantic color.              |

When states overlap, prioritize disabled, loading, blocking error, focus, pressed, selected, hover, then rest. Keep an outcome message visible alongside focus when the person needs both.

## Visual weight

Use the specification's 95/5 principle as a guide to resting visual weight: most of a screen consists of neutral working structure, with a small share for execution, emphasis, and stacking.

Increase emphasis when someone selects a mode, targets a drop region, or needs to resolve an error. Check whether they can recognize the state before reducing its visual weight.

## Influences and identity

IPEX draws operational discipline from Shopify Polaris, tactile control treatment from Clerk, and interaction precision from Linear. Its own identity combines neutral structure, compact density, carbon execution material, semantic feedback, and task-dependent page widths.

A primary action has layered material. A selected working mode feels engaged. An input stays planar. Use elevation when one surface opens above another.

## Authority

For an exact component or screen, follow a supplied canonical IPEX implementation first. Then use the specification's theme and recipes, successful IPEX product screens, and the application's profile. Framework guidance and external references follow those decisions.

This library uses Akaza UI, Tailwind CSS, `tv`, and `cn`. Earlier Nuxt UI examples in the canonical document remain visual and behavioral references. [Styling](/getting-started/styling) describes the current implementation.
