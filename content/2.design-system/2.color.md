Use neutral surfaces for the shell, workspace, panels, and ordinary controls. Apply chroma when it helps someone understand an interaction or outcome.

## Shared roles

The theme uses shadcn's semantic token names with additional shared roles for text emphasis, border strength, and feedback. Read exact light and dark values from the [installed stylesheet](/getting-started/installation#theme-css).

| Role               | Tokens                                     | Use                                                     |
| ------------------ | ------------------------------------------ | ------------------------------------------------------- |
| Workspace          | `background`, `foreground`                 | The current task and its content.                       |
| Panel              | `card`, `card-foreground`                  | A contained region within the workspace.                |
| Floating surface   | `popover`, `popover-foreground`            | Menus, popovers, and overlays.                          |
| Supporting content | `muted`, `muted-foreground`                | Quiet fills and readable secondary text.                |
| Text hierarchy     | `dimmed`, `toned`, `highlighted` utilities | Tertiary details, normal emphasis, and stronger labels. |
| Boundaries         | `border`, `input`, `ring`                  | Separators, control edges, and focus.                   |
| Shell              | `sidebar-*`                                | Navigation surfaces and their states.                   |

Keep a foreground paired with its corresponding background. Use dimmed text for tertiary details; use muted foreground for supporting copy that someone needs to read.

## Action colors

`primary` and `secondary` remain neutral in both themes. Secondary uses a light neutral fill in light mode and the canonical neutral surface mix in dark mode. Use `accent` to opt into IPEX blue for an action; `info` uses the same color family for feedback.

Primary and accent solid buttons use the tactile recipe. Accent uses the original IPEX blue (`#0969da`) in light mode and a lighter blue shade in dark mode. Its light-mode tactile fill starts from a darker shade so white labels remain readable across the gradient. Secondary solid buttons use a flat fill.

For non-solid actions, use a readable emphasis color from the selected role. Tint both backgrounds and borders from that same color. In dark mode, derive secondary emphasis from a lighter shade of its own color. Keep it distinct from primary instead of reusing the solid fill’s contrasting foreground. Use darker chromatic emphasis in light mode and lighter emphasis where needed in dark mode. These derived values preserve the role’s hue and solid fill.

| Variant | Resting fill      | Boundary          | Hover fill                       |
| ------- | ----------------- | ----------------- | -------------------------------- |
| Soft    | 10% emphasis tint | None              | 15% emphasis tint                |
| Subtle  | 10% emphasis tint | 20% emphasis tint | 15% emphasis tint                |
| Outline | Transparent       | 20% emphasis tint | 10% emphasis tint                |
| Ghost   | Transparent       | None              | 5% light / 8% dark emphasis tint |
| Link    | Transparent       | None              | Transparent, with an underline   |

Button backgrounds transition over 200ms on pointer entry and exit, with reduced motion disabling the transition.

These tints remain translucent on the containing surface. Non-solid actions keep matching emphasis text and use no tactile gradient or resting shadow. Field components use their own neutral outline, soft, and bare recipes; they do not inherit an action color.

## Range selection

Calendar, Date Range Field, Date Range Picker, Month Range Picker, and Year Range Picker accept `rangeColor="secondary | accent"`. The default is `secondary`. While choosing an end, hover or keyboard focus previews the items between the endpoints. The committed range keeps that fill; its first and last items use primary.

Use `accent` for a blue-tinted middle or `secondary` for a neutral middle. Set `defaults.rangeColor` in the shared UI configuration to change all compatible pickers.

```vue
<Calendar v-model="dates" selection-mode="range" range-color="accent" />
<DateRangePicker v-model="dates" range-color="secondary" />
<MonthRangePicker v-model="months" range-color="accent" />
<YearRangePicker v-model="years" range-color="secondary" />
```

## Feedback and status

| Role        | Use when                                                                        |
| ----------- | ------------------------------------------------------------------------------- |
| Info        | Work is processing, a drop target is valid, or context needs attention.         |
| Success     | An operation completes, data is verified, or a health check passes.             |
| Warning     | A person needs to review partial data or resolve a caution.                     |
| Destructive | An operation fails, data is invalid, or an action has destructive consequences. |

Separate lifecycle from severity. A queued job can remain neutral. A person cancelling a task does not imply failure. Use a label, icon, or explanation alongside color.

## Theme discipline

Keep the supplied OKLCH base palette and dark surface mixes as the starting point. Preserve optical neutrality in structural surfaces. Use official provider colors for provider identity, while keeping application actions and focus consistent with IPEX.

Syntax highlighting has a separate VS Code-style palette. Code token colors identify language structure and do not indicate product status.
