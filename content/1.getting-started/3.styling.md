## Theme tokens

Edit the shared stylesheet added during [installation](/getting-started/installation#theme-css). Define light values in `:root` and dark values in `.dark`. Use OKLCH values for colors.

```css [app/assets/main.css]
:root {
  --accent: oklch(0.55 0.2 255);
  --accent-foreground: oklch(0.99 0 0);
}

.dark {
  --accent: oklch(0.7 0.15 255);
  --accent-foreground: oklch(0.15 0 0);
}
```

The Tailwind theme maps CSS tokens to utilities. For example, `--background` supplies `bg-background`, and `--accent` supplies `bg-accent`, `text-accent`, and `border-accent`.

| Token or utility                                | Use                                                          |
| ----------------------------------------------- | ------------------------------------------------------------ |
| `background`, `foreground`                      | Page surface and body text.                                  |
| `card`, `popover`                               | Contained and floating surfaces with their foreground pairs. |
| `primary`, `secondary`, `accent`                | Action colors with matching foreground pairs.                |
| `muted`, `muted-foreground`                     | Neutral surfaces and supporting text.                        |
| `text-dimmed`, `text-toned`, `text-highlighted` | Tertiary, secondary, and emphasized text.                    |
| `border`, `input`, `ring`                       | Structural boundaries, field boundaries, and focus.          |
| `info`, `success`, `warning`, `destructive`     | Feedback and status colors.                                  |
| `--radius`                                      | Base radius from which component corners scale.              |

Read [Color](/design-system/color) for the full role descriptions.

## Shared defaults

Use `ui.config.ts` for supported size, color, and variant defaults. This changes component props without editing recipes. See [Usage](/getting-started/usage#defaults) for an example and the resolution order.

## Instance styles

Use `class` to change the root element. Use `ui` to change named parts. Each component's API lists the available parts.

```vue
<Button class="w-full">Create project</Button>
<Button :ui="{ content: 'gap-3' }">Create project</Button>
```

The component merges your classes after its recipe with `cn`. Your overrides take priority.

## Component recipes

Edit the Tailwind Variants recipe in the component's `index.ts` when an application needs a different treatment throughout. Keep styles in Tailwind utilities where possible.

The five sizes are `xs`, `sm`, `md`, `lg`, and `xl`. Change height, padding, text, radius, icon size, and gaps together. The [geometry profiles](/design-system/typography-and-density#geometry-profiles) describe these relationships.

Keep primary and accent solid actions tactile, secondary actions neutral, and state colors consistent. After changing a recipe, check both themes, hover, keyboard focus, disabled states, loading, and touch targets.
