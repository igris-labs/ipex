## Theme tokens

Use shadcn's semantic names, including `background`, `foreground`, `primary`, `secondary`, `accent`, and their foreground pairs. Set light values under `:root` and dark values under `.dark`.

IPEX adds missing roles for dimmed, toned, and highlighted text, border emphasis, inverse surfaces, and semantic feedback. Use `text-dimmed` for tertiary content and `text-muted-foreground` for readable supporting text.

## Component styles

Write styles in Tailwind Variants recipes. Use `cn` to merge each recipe slot with consumer classes. Add custom CSS only when Tailwind cannot express the required behavior.

For primary and accent solid buttons, keep the tactile gradient, edge lighting, and press feedback. Use a flat fill for secondary solid buttons.

## Instance overrides

Use `class` for root changes and `ui` for named parts:

```vue
<Button class="rounded-full px-6">Create project</Button>
<Button :ui="{ content: 'gap-3' }">Create project</Button>
```

Consumer overrides take priority over the recipe. Check text contrast, focus visibility, and loading states after changing colors or dimensions.

## Documentation prose

The documentation site owns its prose components under `app/components/prose`. These components cover headings, paragraphs, lists, links, code, tables, images, quotations, keyboard keys, and semantic callouts. They do not depend on Nuxt UI.

::note{title="One shared theme"}
Prose and interactive components read the same semantic CSS tokens. Change the tokens to theme both together.
::

The documentation highlighter uses Speed Highlight for Vue, TypeScript, CSS, JSON, and shell commands. Code blocks use VS Code Light+ and Dark+ syntax colors, scoped separately from product feedback colors. Code-copy actions preserve the original source text. This documentation dependency is not required when copying IPEX UI components into another application.
