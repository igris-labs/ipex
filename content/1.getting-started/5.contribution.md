## Component structure

Put each component in its own folder under `app/components/ui`. Keep its Vue wrapper in the component's `.vue` file. Put its Tailwind Variants recipe, public types, default-resolution configuration, and exports in `index.ts`.

Use Akaza's documented props, slots, and state hooks. Forward native attributes and events. Preserve returned Promises when a primitive uses them for async loading.

## Styling

Use Tailwind first. Add custom CSS only for behavior that Tailwind cannot express. Use the shared semantic tokens and merge consumer overrides with `cn`.

Define height, padding, typography, radius, icon dimensions, and gaps for each supported size. Update the component page when you change those values.

## Documentation and checks

Write component docs in `content/3.components` with unnumbered filenames, such as `button.md`, so Nuxt Content sorts them by name. Use base folders as category labels and files as pages. Set category titles through `.navigation.yml`; the sidebar reads Nuxt Content's navigation tree.

Use three top-level sections in each component guide: Demos, Installation, and API. Put examples and their code in Demos. Show the core Vue file and index.ts in Installation. Document props, models, slots, events, exposed methods, and keyboard behavior under API. Describe public behavior, supported states, and any limitations.

Import displayed source from the files the examples use. Use the same shared components and size profiles in the landing page, header, footer, and documentation.

Run `pnpm check`, `pnpm test`, and `pnpm build`. Verify keyboard interaction, disabled and loading states, both themes, reduced motion, and a narrow viewport.

## Repository folders

```text
app/
  components/
    ui/             # Copyable components and shared configuration
    content/        # Demos and code presentation
    prose/          # Markdown elements
    docs/           # Search and table of contents
  assets/main.css   # Shared theme
  pages/            # Landing page and document route
content/
  1.getting-started/
  2.design-system/
  3.components/     # Alphabetical component pages
tests/              # Browser checks
```

Nuxt Content builds navigation from these content folders. Each folder's `.navigation.yml` sets its category label. Keep component filenames unnumbered and use frontmatter for the page title, description, and navigation icon.
